# DESIGN Draft — Work-Order Rail (spine-and-tickets)

Run: `create-20260906-issue20-chat` | Phase: canonization | Status: `proposed` | Producer: `system-architect` | Date: 2026-09-06 | Language: EN-US
Selected Direction: `direction-work-order` (spine-and-tickets workbench). Specimen markup was visual reference only and is NOT ported; grammar and values inform tokens below.

---

## 1. Thesis

The session is a job wall where agentic time becomes navigable space: every assistant turn is a numbered work order clipped to a persistent progress spine, so resumption starts with where-was-I instead of scrolling. The spine (`spine.rail`, `spine-nav.*`) is the session's index; tickets (`trace-ticket.*`) are the jobs; the evidence wing (`evidence-wing.*`) is the selected job's attachment sheet. Nothing else on the Surface competes to be the index — one spine per session (L-01), one node per assistant turn, user turns as slim ticks, never nodes.

## 2. Product relationship

This Surface serves accountable delegation: a builder hands consequential coding work to a fast junior and must see what was asked, what the agent did tool by tool, and what changed — scoped to the active session. Every assistant turn that claims work carries ruled tool rows or an explicit empty-trace box (`trace-ticket.empty-trace-border`); failures persist in place with attempt-keeping retry (D-06, L-05); the wing cites back to its ticket (D-05, L-04) so evidence never detaches. Product truths T2–T5 (both sidebars, composer with follow-ups/modes, per-session browser/files/GitHub views, visible Write/Read/Edit/Bash/WebSearch trace) are the skeleton this system dresses; constraints C-T6 (375–1440px, no h-scroll) and C-T5 (real loading/empty/error states) are floors the responsive and state contracts below satisfy.

## 3. Composition grammar

Spine-and-tickets, center-desk plus session-scoped wings. Desktop (1440px): left resume wing (`sidebar.session-bg`, `gap.wing-left`) + spine rail (`spine.rail`, 92px column) + center ticket column (`surface.base`, prose measure `gap.content-measure`) + right evidence wing (`sidebar.evidence-bg`, `gap.wing-right`). Mid widths (≤1180px): the evidence wing becomes a labelled drawer sheet (`dialog.sheet-bg`, `dialog.sheet-border`) tethered to its ticket, announced by `trace-ticket.cite-line`. Small widths (≤820px): left wing becomes a drawer; composer goes sticky-bottom (`composer.sticky-rule`, D-04). Strip width (≤480px): spine compresses to a sticky top progress strip (`spine-nav.node-strip-size`, carriage hidden, nodes tappable at `target.min` hit areas); wings stack as labelled drawers; tool rows obey keep-status/hide-duration (D-03). Reading order is always spine → ticket head → prose → tool rows → well → composer; `gap.section-gap` separates tickets, `gap.stack` separates rows, `gap.cluster` groups related controls.

## 4. Typography roles

Workmanlike grotesk carries the job; mono carries evidence; numerals carry order. Roles and tokens: turn numerals `type.numeral` (desktop) / `type.numeral-strip` (strip), fluid 38–52px, 800 weight, condensed via `font-stretch` on the offline-safe stack `font.numeral` (D-09, never Impact-dependent); ticket titles `type.header` (16px semibold); prose `type.body` (14–15px, `gap.content-measure` line length); ticket meta and spine labels `type.meta` / `type.micro` (11–12px uppercase, letterspaced); tool targets, commands, durations and cite lines `type.mono` / `type.duration` (mono rationed strictly to evidence, L-06); chrome labels and drawer tethers `type.eyebrow`; composer hints and honest stub labels `type.hint`. Voice contrast does hierarchy: jobs shout numbers, tools whisper targets. No other faces enter without a Decision.

## 5. Color

Quiet grounds carry reading; saturated color is rationed to status and diff (L-07). Grounds: `surface.base` (paper), `surface.wing` (deeper tool walls), `surface.ticket` (card), `surface.well` (inset wells). Ink scale `text.primary` / `text.secondary` / `text.muted` — all AA against grounds (see validation §2). Signal triad via `status.*`: ok `status.ok-ink` on `status.ok-bg`, caution `status.warn-ink` on `status.warn-bg`, failure `status.bad-ink` on `status.bad-bg` — every state pairs color with glyph plus word (L-03), so the rail survives grayscale. Diff green/red (`diff.*`) live strictly inside expanded wells. The spine rail itself stays neutral `spine.rail`; only nodes carry status fill (`spine-nav.node-ok/run/bad/idle`). Selection earns one restrained accent edge `action.accent-edge`, never a tint. Links and change markers use `action.accent`; focus is always the 3px `focus.ring`. No AI gradient, no ambient glow, no shimmer — motion color is limited to the running pulse `feel.pulse`.

## 6. Surfaces

The ticket stack is the one territory where cards are structural: a work order is a bounded job with attachments, not a message. CARD-SOUP GUARD (L-02, absolute): exactly one ticket per viewport carries `lift.active` (the selected work order) plus `action.accent-edge`; all others are flat with 1px `border.rule`; tool rows are hairline-ruled (`trace-ticket.tool-row-border`), never cards; expansion happens in an inset well (`surface.well`) inside the same ticket, at most one well open per work order; the spine is a plain rule with nodes, never elevated; the right wing is tethered by shared citation (`evidence-wing.cite-line`), never a floating panel; emphasis uses numerals, labels and pips, never extra shadows. Depth means job state — a shadow anywhere else is a defect.

## 7. Shape

Workshop-sharp with the smallest softening that keeps chrome touchable. Corners: `radius.none` on tickets, wells, spine nodes (round nodes excepted: nodes are true circles, the rail's rivets) and composer frame; `radius.sm` on pills, kind chips, buttons and inputs. Ticket spine-side edge is a 5px state/rule bar (`trace-ticket.edge-idle/active/failed/running`); session items echo it with `sidebar.item-active-edge`. Borders: `border.hair` inside tickets, `border.rule` between components, `border.strong` for the composer frame and drawer sheets. No other radius or edge treatment enters without a Decision.

## 8. Spacing

Numeric sizes live in primitives (`space.*`); behavior lives in the eight semantic roles (`gap.*`), and prose here cites roles, never pixels: `gap.inline` (4px — glyph-to-label inside pills and status rows); `gap.stack` (12–16px — ticket head to prose to tool list to well); `gap.cluster` (8–10px — kind chip to target to status within a tool row, follow-up to follow-up); `gap.control-padding-x/y` (12–16px / 10–12px — button, tab, mode-toggle and follow-up padding around the 44px `target.min` floor); `gap.card-padding` (14–16px — ticket, well, panel and sheet insets); `gap.section-gap` (18–24px — ticket to ticket, wing section to section); `gap.page-gutter` (26px desktop, 12px strip — center column and wing insets); `gap.content-measure` (70ch — prose and stamp wrap width). Density is rhythmic: compact 44px rows (`target.row`), one expanded well, history compressed to nodes — compression removes pixels between jobs, never inside controls.

## 9. Motion

Motion narrates the job lifecycle along the rail (D-12): queued enters at the spine base (`feel.enter`); running shows the amber node pulse `feel.pulse` with opacity steps plus staged determinate-feeling progress honestly labelled synthetic (`trace-ticket.staged-honest`); terminal states settle once to green/red with no flash beyond one settle (`feel.settle`); the composer echoes optimistically then docks within `feel.echo` (300ms ceiling, C-P1); spine scrub cross-highlights ticket, node and wing header together (`feel.snap`); interrupt and retry acknowledge instantly. Reduced motion (`feel.reduce`): every animated state has a static equivalent — pulse becomes a stepped icon swap, progress becomes step text (Step 2 of 4), echo becomes instant dock, scrub becomes instant jump. Prose streams caret-only, never shimmer; auto-scroll never yanks — the carriage marker (`spine.carriage-bg`) shows position instead.

## 10. Signature

The spine navigator — the time rail doubled as session navigation. A continuous 2px `spine.rail` with one node per assistant turn in chronological order; nodes coded by status color plus glyph plus word (`spine-nav.node-ok/run/bad/idle`); failures as persistent red nodes with counts until retried or dismissed with reason (D-06); the viewport position shown as a carriage marker (`spine.carriage-bg`); click or keyboard scrub jumps the center column and mirrors selection in the evidence wing. Regulation (L-01): exactly one spine per active session; exactly one node per assistant turn (user turns are ticks); at most one well open per work order; 20+ turns compress completed runs to counts while failures and the current job stay addressable with jump-to-failure. It recurs on every multi-turn session — docked rail at desktop, compact top strip at 375px. Any second rail, or any node that is not a turn, breaks the signature.

## 11. Surface variants

1440px docked workbench: three panes plus spine, composer in-flow, full spine labels with counts. ≤1180px: evidence wing becomes a tethered drawer sheet (`dialog.sheet-bg`) labelled by citation; spine keeps labels, hides durations. ≤820px: left wing to drawer; composer sticky-bottom (`composer.sticky-rule`); wing meta translates to footnotes below the stack (D-08, `evidence-wing.footnote-text`). ≤480px strip: spine to sticky top strip, carriage and collapse-note hidden, nodes at `target.node-strip` visuals with `target.min` hit areas; ticket heads roll up status (D-11) and hide durations (D-03); tool rows keep status glyphs, hide durations; prose stays at `type.body` with `gap.page-gutter` 12px; no horizontal scroll at any width (L-08). Evidence views are attachment variants of one contract: browser excerpt, file tree (`table.*` rows, `action.accent` change dots) and GitHub checks (`table.*` with AA status rows) — each with its empty view (dashed `evidence-wing.empty-border` frame plus recovery action) and each stamped by `evidence-wing.cite-line`. Empty session shows an unclipped spine with a starter ticket; streaming shows skeleton rows resolving to tickets; queued shows idle nodes with honest labels.

## 12. Do / Avoid

Do: scan the spine to resume — numbers then status words then pills. Do: expand one well per ticket and cite it back — the wing header must read `Turn NN / Kind target`. Do: retry from the failed ticket with its attempt-keeping label — history stays visible. Do: keep every status as color plus glyph plus word at every width — hide duration first. Do: let numerals shout and targets whisper — grotesk for jobs, mono for evidence. Avoid: bubbles, avatars and alternating message colors — turns are jobs (`trace-ticket.bg`), not chat. Avoid: elevating a second ticket, carding a tool row, or tinting selection — depth means job state (L-02). Avoid: tinted kind chips or status-by-hue — hue means status or diff only (L-07). Avoid: toasts, auto-dismiss, auto-scroll yanks and shimmer — failures persist in place with live-region announcement. Avoid: CDN faces or Impact-shaped numerals — the stack boots offline (C-P2) with `font.numeral`. Avoid: dropping wing meta at narrow widths — translate it to footnotes (D-08).

## 13. Exceptions pointer

Seven departures from specimen values or Run defaults are recorded with reasons in the exceptions record (validation report, section 6): EX-01 darkened status inks for AA; EX-02 neutral kind chips; EX-03 Impact-free numeral stack; EX-04 44px floor on small controls; EX-05 strip-spine label simplification; EX-06 cmdout dark block retained as the single dark intent; EX-07 footnote translation of wing meta. No other departure is authorized: any value in build that is neither a token nor a listed exception is a defect, and any unlisted exception discovered at audit is reported as a violation, not a precedent.
