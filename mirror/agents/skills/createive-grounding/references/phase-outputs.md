# Grounding Phase Outputs

Required elements per artifact. The Phase Packet names which one to produce; `acceptance` in that Packet is the binding bar, and this file is the default shape when the Packet is silent.

## Product Brief

`CREATE / grounding` — gate `grounding-completeness`

Actual user and context of use; primary task; desired user and business outcome; product truths; content and data contracts; constraints; desired perception as operational qualities; differentiation; open creative space. Confidence per inferred field, since the gate checks that field-by-field rather than as a single overall score.

## Constraint Draft

`CREATE / grounding`

Technical, legal, accessibility, localization, and performance constraints. Each constraint names its source and whether it is a hard floor or a current assumption — a later Role treats those differently.

## Surface Brief, Information Architecture, Responsive Model, State Matrix

`CREATE / surface-architecture`

Focal outcome; primary and secondary actions; information tiers; progressive disclosure; required states; responsive transformations. Exit bar is implementation-readiness: a builder should not need to invent behavior for any state or breakpoint you list.

## Product Truths, Behavior Contracts, Preserve/Replace Matrix

`REDESIGN / preserve-product-truth` — gate `grounding-completeness`

Four separated sets: product truth and behavior to preserve; technically strong assets to preserve; visual expression free to change; architecture needing evidence before replacement. Every "replace" entry carries the evidence for replacing. Every entry cites the Baseline or documentation it came from.

## Creative Question

`EXPLORE / frame-question` — gate `grounding-completeness`

The product-specific tension; the constraints any answer respects; the default answer to overcome. Exit bar is that the question separates creative uncertainty from implementation choice.

## Eligibility Report

`EXPLORE / eligibility` — gate `direction-eligibility`

Per candidate: a verdict against product truth, usability, required states, responsiveness, and implementation viability. Each ineligible verdict names the specific truth, Lock, or constraint violated. Gate passes when no blocker remains.

You judge these independently of the creators. Comparative ranking and quality judgment belong to the visual-critic.

## Opportunity Map

`DOCUMENT / opportunity-map`

Per opportunity: Evidence, impact, root cause, scope, possible paths, expected proof of resolution. Plus a Workflow recommendation (maintenance, `REFINE`, or `REDESIGN`) with the reasoning; the Coordinator routes.
