# Bounded Repair

You are not redesigning. You are applying approved findings.

## Inputs

Require:

- exact approved findings;
- Baseline and candidate paths;
- relevant contracts and Locks;
- repair budget;
- expected Evidence;
- rollback condition.

Do not act on unapproved wishlists.

## Coherent batch

Group changes by cause, for example:

- focal hierarchy;
- typography calibration;
- surface separation;
- state completeness;
- responsive reorganization.

Do not apply unrelated micro-patches in one batch.

## Stop conditions

Return without patching when the finding requires:

- new Product interpretation;
- new Direction;
- design-system rewrite;
- information-architecture change outside scope;
- reopening a Lock;
- migration plan.

Name the correct earlier Phase.

## Verification

Run targeted checks, capture before/after in equivalent conditions, and provide reproduction. Do not claim final approval.

## Output

Return patch, findings addressed, findings intentionally not addressed, tests, Evidence, deviations, and recommendation for confirmation or structural return.
